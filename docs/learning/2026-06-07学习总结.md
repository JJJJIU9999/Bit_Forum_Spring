## 新名词解释

### DTO

DTO 是 Data Transfer Object，意思是“数据传输对象”。

它的作用是隔离数据库实体和接口返回值。比如 `User` 实体里有 `password`，但注册接口不应该把密码哈希返回给前端，所以用 `UserResponse` DTO 只返回 `id`、`username` 等安全字段。

面试说法：

> 我没有直接把数据库实体暴露给前端，而是用 DTO 控制接口出参，避免敏感字段泄露。

### Request DTO

Request DTO 是专门接收请求参数的对象。

后面 M5 会做这个，比如把注册参数从散落的 `username`、`password` 改成 `UserRegisterRequest`，再配合 `@Valid` 做参数校验。

### Response DTO

Response DTO 是专门返回给前端的对象。

你已经做过 `UserResponse`，它就是 Response DTO。

### Spring Bean

Spring Bean 指的是交给 Spring 容器管理的对象。

比如 `JwtUtil` 改成 `@Component` 后，就不再靠自己 `new` 或静态方法调用，而是由 Spring 创建并注入给 `UserController`、`LoginInterceptor` 使用。

### 配置外置

配置外置就是把容易变化或敏感的内容从代码里拿出来，放到 `application.yml` 或环境变量里。

比如 JWT 密钥以前写死在 `JwtUtil` 里，现在从配置读取。这样部署到不同环境时不用改 Java 代码。

### `@ConfigurationProperties`

它可以把 `application.yml` 里的配置绑定到 Java 对象上。

比如 `jwt.secret`、`jwt.expiration` 可以绑定到 `JwtProperties`，然后 `JwtUtil` 通过这个对象读取配置。

### Interceptor

Interceptor 是拦截器。

你的 `LoginInterceptor` 用来拦截需要登录的接口，从请求头里取 JWT，解析用户 ID，再把 `userId` 放到请求上下文里。

### GlobalExceptionHandler

全局异常处理器。

它集中处理 Controller 抛出的异常，避免每个接口都写重复的 try-catch。你现在已经把未知异常改成服务端记录详细日志、客户端返回固定提示，避免泄露内部细节。

### Flyway

Flyway 是数据库迁移工具，可以理解成“数据库结构版本管理”。

它会按 `V1__xxx.sql`、`V2__xxx.sql` 的顺序执行 SQL，并用 `flyway_schema_history` 表记录哪些脚本已经执行过。

面试说法：

> 我用 Flyway 管理数据库初始化脚本，让新环境启动时可以自动建表，也方便团队知道数据库结构改过哪些版本。

### migration

Migration 就是数据库迁移脚本。

你的 `V1__init_schema.sql` 就是第一版数据库结构脚本，负责创建用户、文章、评论表。

### baseline-on-migrate

这是 Flyway 的一个配置。

当一个数据库已经手工建过表，但还没有 Flyway 历史表时，Flyway 默认会拒绝接管。`baseline-on-migrate: true` 表示允许 Flyway 先建立历史记录，然后从当前状态开始管理。

### Docker 多阶段构建

多阶段构建就是一个 Dockerfile 里分两个阶段：

- builder 阶段：用 Maven + JDK 从源码打包 JAR。
- runtime 阶段：用更轻的 JRE 镜像只运行 JAR。

好处是最终镜像更干净，也不依赖本机提前生成 `target` 目录。

### JDK 和 JRE

JDK 是 Java Development Kit，用来开发和编译 Java 程序，里面有 `javac`。

JRE 是 Java Runtime Environment，只负责运行 Java 程序。生产镜像里通常用 JRE 就够了。

### `.dockerignore`

它告诉 Docker 构建镜像时哪些文件不要复制进去。

比如 `target/`、`.git/`、日志文件都不应该进入镜像构建上下文，否则构建会慢，也可能带入无关文件。

### Docker Compose service name

在 `docker-compose.yml` 里，`mysql`、`redis`、`rabbitmq`、`app` 都是服务名。

容器之间在同一个 Compose 网络里通信时，不用写 `localhost`，而是用服务名。比如后端容器连接数据库时用 `mysql:3306`。

### 端口映射 `3307:3306`

左边是宿主机端口，右边是容器内端口。

`3307:3306` 的意思是：你电脑访问 `localhost:3307`，会转发到 MySQL 容器里的 `3306`。这样可以避开本机已有 MySQL 占用 `3306` 的问题。

### allowPublicKeyRetrieval

这是 MySQL 8 连接参数。

当 MySQL 使用某些认证方式时，客户端可能需要获取服务端公钥。没有这个参数时会报 `Public Key Retrieval is not allowed`。

### RabbitMQ 启动时序

Compose 的 `depends_on` 只能保证容器启动顺序，不保证服务已经完全 ready。

所以 app 可能先连 RabbitMQ 失败一次，之后 RabbitMQ ready 了又自动重连成功。看到最终 `Created new connection` 才是关键。

### `@SpringBootTest`

它会启动完整 Spring 容器，适合测试 Service、Mapper、配置、事务等组件是否能真实协作。

缺点是比普通单元测试慢一些，但更接近真实运行环境。

### `@Transactional` 用在测试上

测试类或测试方法加 `@Transactional` 后，测试结束会自动回滚数据库改动。

比如发布文章测试里插入了测试文章，但测试结束后不会污染本地数据库。

### `@MockBean`

`@MockBean` 会在 Spring 容器里放一个假的 Bean，替换真实 Bean。

你在 `ArticleServiceTest` 里 mock 了 `RabbitTemplate`，这样测试发布文章时不会真的依赖 RabbitMQ，只验证“发送方法被调用过”。

### Mockito verify

`verify(...)` 是 Mockito 的验证方法。

比如：

```java
verify(rabbitTemplate).convertAndSend(...)
```

意思是确认这次测试过程中，`convertAndSend` 这个方法确实被调用过。

### assertThrows

`assertThrows` 用来测试“某段代码应该抛异常”。

你在“非作者不能删除文章”测试里用它验证了权限校验失败时会抛出 `RuntimeException`。

### QueryWrapper

`QueryWrapper` 是 MyBatis-Plus 提供的查询条件构造器。

它可以用 Java 代码构造 SQL 条件，比如：

```java
wrapper.eq("article_id", articleId);
```

相当于 SQL 里的：

```sql
WHERE article_id = ?
```

### Redis Set

Redis Set 是集合结构，天然不允许重复元素。

所以点赞功能用 Set 很合适：同一个用户 ID 加入同一篇文章的点赞集合，多次添加也只算一个成员。

### 幂等性

幂等性指的是同一个操作执行一次和执行多次，最终结果一致。

比如同一个用户重复点赞同一篇文章，点赞数量仍然是 1，这就是点赞接口的幂等性体现。

### 脏数据

脏数据指的是不应该存在、但因为业务校验不完整而被写入的数据。

比如对不存在的文章插入评论，就是脏评论。你今天用测试验证了这种数据不会插入。

### 回归测试

回归测试是为了防止以后改代码时把已经修好的问题又改坏。

比如“评论不存在文章失败”这个测试，以后只要有人不小心删掉文章存在校验，`mvn test` 就会失败。

### 冒烟测试

冒烟测试是最基础的“系统能不能跑起来”的测试。

比如 Docker Compose 启动后访问 `/api/article/listAll`，能返回 200，就说明后端服务、端口和基本依赖是通的。

## 今天遇到的问题和解决方式

### Maven 下载 Flyway 失败

现象：Maven Central TLS 握手失败。

处理：重试后本机下载成功；Docker 构建时又通过 `maven-settings.xml` 配置 Maven 镜像源改善下载稳定性。

### Flyway 接管旧数据库失败

现象：已有数据库不为空，但没有 Flyway 历史表。

处理：在 `application.yml` 配置 `spring.flyway.baseline-on-migrate: true`。

### Docker MySQL 端口冲突

现象：宿主机 `3306` 被占用。

处理：把 Compose 端口映射改为 `3307:3306`，后端容器内部仍然连接 `mysql:3306`。

### MySQL Public Key Retrieval 报错

现象：连接 MySQL 时报 `Public Key Retrieval is not allowed`。

处理：JDBC URL 增加 `allowPublicKeyRetrieval=true`。

### RabbitMQ 首次连接失败

现象：app 启动时 RabbitMQ 还没完全 ready，出现一次 `Connection refused`。

处理：观察后续日志，确认出现 `Created new connection`，说明自动重连成功。
