## 已纠正的概念

### 1. `form` 不是组件

错误说法：

```text
form 状态组件
```

准确说法：

```text
form 是 React 里的状态对象，用来暂存 username/password。
```

当前登录页里的形状大致是：

```js
{
  username: '用户输入的用户名',
  password: '用户输入的密码'
}
```

### 2. `onChange` 和 `onSubmit` 不一样

`onChange`：

```text
输入框内容变化时触发，用来更新前端 form 状态。
```

`onSubmit`：

```text
表单提交时触发，用来执行登录请求。
```

当前链路：

```text
input 输入变化
-> onChange={updateField}
-> setForm(...)
-> form 状态更新

点击登录按钮
-> form onSubmit={handleSubmit}
-> handleSubmit
-> loginUser(form)
```

### 3. 前端不是把 `loginUser` 传给后端

错误理解：

```text
后端收到 loginUser 传来的参数。
```

准确理解：

```text
loginUser(form) 是前端函数，它会发出 HTTP 请求。
后端收到的是 POST /api/user/login 请求，以及请求体里的 username/password。
```

### 4. `result.data` 是取字段，不是调用方法

当前代码：

```js
saveAuth(result.data)
```

含义：

```text
从后端返回结果 result 里取 data 字段，再交给 saveAuth 保存。
```

### 5. 后端不是随机分配 Controller

准确理解：

```text
Spring MVC 根据请求方法和路径匹配 Controller 方法。
POST /api/user/login 会匹配到：
UserController 类上的 @RequestMapping("/api/user")
加上 login 方法上的 @PostMapping("/login")
```

所以最终进入：

```text
UserController.login(...)
```

### 6. DTO 的作用不是简单“防止数据污染”

更准确地说：

```text
DTO 用来定义前后端这一条接口要传什么数据、返回什么数据。
```

它的作用包括：

```text
1. 限制入参形状，前端只能按 DTO 接口约定传字段。
2. 配合 @Valid 做参数校验。
3. 避免直接暴露 Entity，比如不把 password 返回给前端。
4. 让接口数据结构和数据库表结构解耦。
```

### 7. BCrypt 不是简单“重新加密后比较字符串”

准确理解：

```text
登录时不会把明文密码简单加密一次，再直接和数据库密文做字符串相等比较。
```

原因：

```text
BCrypt 每次加密都会带随机 salt，所以同一个明文密码，多次加密出来的密文通常不一样。
```

当前代码：

```java
encoder.matches(password, user.getPassword())
```

含义：

```text
password 是用户这次输入的明文密码。
user.getPassword() 是数据库里保存的 BCrypt 密文。
matches 会从密文里解析 salt 和参数，再用同样规则验证这个明文是否匹配该密文。
```

### 8. `Jwts.builder()` 是 JWT 库提供的创建器入口

准确理解：

```text
Jwts 是 jjwt 库提供的工具入口类。
builder() 是它的静态方法，用来创建一个 JWT 构建器对象。
```

所以这句：

```java
Jwts.builder()
```

可以理解成：

```text
请给我一个用来组装 token 的 Builder。
```

后面的链式调用：

```java
.subject(username)
.claim("userId", userId)
.issuedAt(now)
.expiration(expireDate)
.signWith(key)
.compact()
```

可以理解成：

```text
往 token 里填用户名、用户 ID、签发时间、过期时间，再用密钥签名，最后打包成字符串。
```

## 当前已理解的小链路

### Login.jsx

核心链路：

```text
用户输入用户名和密码
-> input 的 onChange 调用 updateField
-> updateField 调用 setForm
-> username/password 暂存在 form 状态对象
-> 用户点击登录
-> form 的 onSubmit 调用 handleSubmit
-> handleSubmit 调用 loginUser(form)
```

### userApi.js

核心代码：

```js
export function loginUser(payload) {
  return request.post('/user/login', payload)
}
```

理解：

```text
payload 就是 Login.jsx 传进来的 form。
request.post('/user/login', payload) 表示发 POST 请求。
请求体里带 username/password。
```

### request.js

核心代码：

```js
const request = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || '/api',
  timeout: 10000,
})
```

理解：

```text
如果配置了 VITE_API_BASE_URL，就用配置的后端地址。
如果没有配置，就默认用 /api。
```

本地默认链路：

```text
request.post('/user/login', form)
-> baseURL 默认 /api
-> 浏览器实际请求 /api/user/login
-> Vite 代理转发到 Spring Boot
-> http://localhost:8080/api/user/login
```

```text
Login.jsx

```

今天重点纠正并理解了：

```text
1. form 是 React 状态对象，不是组件。
2. onChange 更新表单状态，onSubmit 才是提交登录。
3. 后端收到的是 HTTP 请求和 JSON 请求体，不是 loginUser 函数。
4. DTO 用来定义接口入参/出参，避免直接暴露 Entity。
5. BCrypt.matches 不是简单重新加密后比较字符串。
6. JWT claim 可以保存 userId 这类少量身份字段，不能放密码等敏感信息。
7. TOKEN_KEY / USER_KEY 是 localStorage 的 key 名，不是保存 token 的变量本身。
8. localStorage 只能保存字符串，所以对象要用 JSON.stringify，读取时用 JSON.parse。
```

当前停在：

```text
登录成功后，前端已经把 token 和 userId/username 保存到 localStorage。
```

## 三个核心概念

认证：

```text
你是谁？
登录成功后，后端返回 JWT。
```

权限：

```text
你能不能进这个接口？
LoginInterceptor / AdminInterceptor 负责判断。
```

业务归属：

```text
这个资源是不是你的？
例如只能改自己的文章，不能点赞自己的文章。
这类判断通常在 Service 里。
```
