## 一、已跑通的小样本评测（20 条合成样本）

样本来源：`scripts/ai-eval/moderation-dev-samples.json`，**人工构造的合成评测集**，不是线上真实数据。
标注依据：第一轮决策第 4 条 —— 明确违规判 `REJECT`，模糊内容判 `REVIEW`，正常内容判 `PASS`。

| 指标 | 数值 | 口径说明 |
| --- | --- | --- |
| 严格准确率 | 85.0%（17/20） | 三档判断与标注完全一致 |
| **漏放率** | **0.0%**（0/8） | 标注 REJECT 却判 PASS（最危险） |
| 安全召回率 | 100.0%（8/8） | 标注 REJECT 且判 REJECT 或 REVIEW |
| **误伤率** | **0.0%**（0/7） | 标注 PASS 却判 REJECT |
| REJECT 精确率 | 80.0%（8/10） | 判 REJECT 中真正该拒绝的比例 |
| REJECT 召回率 | 100.0%（8/8） | 该拒绝的内容被判 REJECT 的比例 |

**一句话**：明确的违规内容一个没漏、正常内容一个没误伤；扣分全部来自"模糊内容"的档位选择。

## 三、需要你帮我判断的三个问题

### Q1. REVIEW 类样本被判成 REJECT 或 PASS，算不算"错"？

这直接决定严格准确率的分母怎么算，也决定后续提示词往哪个方向调。

三个候选口径：

- **A（严格）**：三档必须完全一致，当前口径，准确率 85%；
- **B（安全导向）**：只考核两件事 —— 标注 REJECT 的不许判 PASS（漏放=0）、标注 PASS 的不许判 REJECT（误伤=0）；
  REVIEW 样本判成 REJECT 或 PASS 视为"可接受的保守/宽松偏差"，不计入扣分；
- **C（混合）**：主指标用 B，同时报告严格准确率作为参考。

我倾向 C，但这会影响答辩时怎么表述，需要你判断。

### Q2. "灌水 / 无意义内容"到底算不算违规？

dev-014 与 dev-015 都卡在这个问题上，而**社区规则里目前没有定义灌水**。

- 如果算违规 → 标注应该是 REJECT，模型判 REJECT 就是对的（当前标注偏松）；
- 如果不算违规 → 标注应该是 PASS，模型就没错；
- 如果要"提醒管理员但不当违规" → 才是 REVIEW。

这题必须先有社区规则，模型才可能判对。你倾向哪种？

### Q3. 自动放行阈值的量级是否合理？

开发集上「标注 PASS 且 AI 判 PASS」的 7 条样本，置信度最低 0.90、风险分最高 0.10，
因此**宽松边界**是 `confidence ≤ 0.90`、`risk > 0.10`（让正常内容全部能自动放行）。

但这是 20 条样本算出来的，样本太少。你建议：

- 直接用这个量级扩到 100 条验证？
- 还是先取更保守的值（例如 confidence ≥ 0.95、risk ≤ 0.05），宁可少放行也不冒险？

## 四、我方助手的初步看法（供批判）

1. Q1 选 C：安全指标（漏放率、误伤率）作为主指标，严格准确率作为参考。
   理由：M16 的实际用途是"减少人工工作量 + 不放过违规"，三档完全一致并不是业务目标。
2. Q2 建议**先定义规则再评测**：把"灌水"要么明确写进违规清单，要么明确排除；
   悬空状态下模型怎么判都不算错，评测也就没有意义。
3. Q3 建议先保守（0.95 / 0.05）扩到 100 条，用测试集数据再放松 —— 自动放行是唯一会自动改变
   线上状态的动作，宁可少放。
