# M16 审核策略决策简报（拿去和外部 AI 讨论）

> **用法**：先粘贴 `scripts/project-overview.sh` 生成的项目全景，再粘贴本文件，
> 然后让外部 AI 回答第四节的六个问题。
> **本文件只讨论产品策略选择**——技术可行性已在 T7 验证中确认（见第二节），不需要再讨论"能不能做"。

---

## 一、M16 要做什么

给论坛加一个 **AI 内容审核 Agent**，参与真实的审核流程：

- 文章：作者提交后进入 `PENDING` 人工审核队列（**先审后发**）。AI 在人工审核前给出风险判断。
- 评论：`publish()` 直接入库、**发布即公开**，没有审核环节。AI 只能在**发布之后**做检测。
- 管理端：展示 AI 的风险判断与理由，管理员可标记「AI 判断正确 / 错误」，形成人工反馈闭环。
- 最终要产出评测数据：准确率 / 精确率 / 召回率 / 漏判率。

## 二、技术层面已经确认的事（不再是风险）

已做 T7 前置验证（`findings.md` 6.12），结论：

- 让模型返回结构化结果（各维度评分 + 决策 + 置信度 + 理由）**能被稳定解析成 Java 对象**：
  两轮实验共 16 次调用，**解析成功 16/16、字段完整 16/16**。
- 所以「AI 能不能输出可用的结构化审核结论」这个问题**已经有确定答案：能**。

## 三、我实际拿到的对照数据

同样的 8 条样本，只换提示词，结果差异很大：

| 提示词 | 解析成功 | 字段完整 | 决策与我的预期相符 |
| --- | --- | --- | --- |
| A：只说"保守优先，拿不准就转人工"，**不给 REJECT 判据** | 8/8 | 8/8 | **5/8** |
| B：逐条写出"什么情况算 REJECT" | 8/8 | 8/8 | **8/8** |

逐条对比（`PASS` / `REVIEW` / `REJECT` 分别表示"放行"/"转人工"/"拒绝"）：

| 样本 | A 版结果 | B 版结果 |
| --- | --- | --- |
| 正常技术文章 | PASS | PASS |
| 明显广告（"加微信 abc123 领课程"） | **REVIEW** | REJECT |
| 灌水（连续重复"顶"字） | REVIEW | **PASS** |
| 人身攻击（"楼主就是个傻子…"） | **REVIEW** | REJECT |
| 正常技术评论 | PASS | PASS |
| 软性引流（"方法放在我主页了"） | REVIEW | **REJECT** |
| 疑似诈骗（"填身份证银行卡领补贴"） | **REVIEW** | REJECT |
| 敏感话题（"建议私下讨论"） | REVIEW | REVIEW |

**两个观察**：

1. 模型**有能力**给出 REJECT（B 版证明），A 版"什么都不敢拒"是提示词没给判据造成的。
2. 但 B 版把判据写成清单后，模型变得**机械**：连"方法放在我主页了"这种模糊表述也直接 REJECT，
   有误伤正常内容分享的风险。**判据的松紧需要产品侧定规则，不是技术问题。**

## 四、需要你帮我判断的六个问题

### Q1. 审核分几档？各档的后果分别是什么？

我的候选：`PASS`（放行）/ `REVIEW`（转人工）/ `REJECT`（拒绝）。

但关键不是名字，而是**后果**。特别地：
- 文章是"先审后发"，所以 AI 判 REJECT 时，是"建议管理员驳回"还是"可以直接驳回"？
- 评论是"发布即公开"，AI 判 REJECT 时不可能撤回，那它到底代表什么动作？
  （我的候选：生成一条高优先级待处理记录 + 通知管理员，**不自动删除**，因为已经公开了）

### Q2. 灌水怎么处理？

论坛是否把"连续重复字顶帖"视为违规？这直接决定判 REVIEW 还是 PASS。
（这题我倾向交给产品定，而不是让模型猜。）

### Q3. "软性引流 / 边界模糊内容"怎么处理？

B 版直接 REJECT 了"方法放在我主页了"。但这句话也可能是正常用户在分享经验。
你倾向：宁可误伤（严格）还是宁可放过（宽松）？有没有更好的中间做法？

### Q4. AI 自动放行要不要默认开启？阈值怎么定？

计划书要求"可配置开关，答辩演示自动与转人工两条路径"。
我倾向：**默认关闭**（AI 只给建议、人来决定），演示时打开。
如果开启，你认为阈值该怎么定？例如"decision=PASS 且 confidence ≥ 0.9 且所有维度分 < 0.3"是否合理？

### Q5. 评论"事后检测"的语义，会不会有法律/体验上的坑？

评论已经公开了才被 AI 判定违规，此时"拒绝"其实只是"提醒管理员去看"。
这种设计有没有问题？有没有更合适的处理方式（比如评论也改成先审后发）？
（注意：改成先审后发会**改变现有产品行为**，现在评论发出去立刻可见，影响面较大。）

### Q6. 风险维度怎么设计？

计划书里是四个：违规内容、广告推广、灌水、敏感信息。
从实测看，模型对"每个维度给 0~1 分 + 一句理由"执行良好。
你认为这四个维度是否需要增删？是否需要"综合分"？

## 五、另一个 AI 助手（DSH）的初步倾向（供你批判）

> 以下是我平时协作的编码助手给出的倾向，**不是最终决定**，请你评估是否合理、哪里有问题。

1. **三档决策保留，但 REJECT 的语义统一为"高优先级提示人工"，不自动删除任何内容**——理由：误判代价不对称，
   错删用户内容比漏放一条更难挽回。
2. **灌水判 REVIEW 而非 PASS 或 REJECT**——理由：灌水判定主观、易误伤，交给人工成本低。
3. **软性引流判 REVIEW**——理由：避免 B 版那种机械 REJECT 误伤正常分享。
4. **自动放行默认关闭**，开启时要求 PASS 且高置信度，且**只对文章生效**（评论已公开，放行无意义）。
5. **评测样本人工构造 100 条**并如实标注来源（不伪称"真实业务数据"）。
