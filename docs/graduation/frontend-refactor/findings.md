# 前端重构审查结论

## 当前问题

- `App.jsx` 依赖内存中的 `activePage`、`adminTab` 和选中 ID 切换视图，导致刷新、深链接、分享和浏览器历史失效。
- `style.css` 超过 1200 行，只有一个局部移动端断点；主导航、搜索、个人页、管理侧栏和表格在小屏下没有完整布局。
- `ArticleCard` 在存在 `children` 时会在操作区和底部重复渲染；登录卡片和后台内容容器已有 CSS 却未接入 JSX。
- `ConfirmDialog` 缺少对话框语义、Escape、焦点圈闭和关闭后的焦点恢复；页面没有统一 `focus-visible`、跳过导航链接和 live region。
- 个人资料、文章、收藏和举报被压在 `MyArticles` 中；管理端每页都先做健康检查，普通用户也能看到后台入口。

## 设计基线

- 页面底色：纸张米白；内容表面：暖白；文字：深墨；交互主色：砖红；成功/辅助：苔绿。
- 标题使用本机可用的中文衬线字体栈，正文使用中文无衬线字体栈；不请求远程字体。
- 桌面首页采用文章主栏与热门/板块侧栏；窄屏改为单列并使用移动底部主导航。
- 管理端桌面保留深色侧栏，窄屏使用可关闭抽屉；数据表小屏变为记录卡而非整页横向滚动。
- 动效仅使用 150-220ms 的 CSS 过渡，并尊重 `prefers-reduced-motion`。

## 非目标

- 不增加作者昵称、头像或互动状态等新的文章接口字段。
- 不增加图表、富文本、暗色模式、对象存储、状态管理或 UI 组件库。
- 不改变后端鉴权、审核、上传、消息、Redis 和数据库业务逻辑。

## 已落地的取舍

- 保持原有 API 封装和业务端点不变；唯一后端契约调整是登录成功时额外返回既有的用户角色。
- 管理表格在小屏保留其容器内横向滚动，以避免页面级横向滚动且不复制七套数据表的显示逻辑；导航切换为抽屉。
- 管理页不再在每次列表请求前调用健康检查；健康检查只保留在管理员看板入口，业务接口继续由后端权限拦截器保护。
- 使用本地系统字体栈和 CSS token 达成视觉升级，不引入远程字体或新的 UI 框架。
