# 毕业设计文档总览

## 项目名称

基于 Spring Boot 与 React 的多智能体智能社区平台设计与实现

> 原名称「基于 Spring Boot 与 React 的社区交流平台设计与实现」在 M1-M12 阶段使用。M13 起接入大模型与 AI Agent 能力，项目定位升级为多智能体智能社区平台。

## 文档定位

本文是 `docs/graduation/README.md` 的中文替代文件，用于记录毕业设计改造的总体目标、当前能力、模块路线和文档入口。

项目当前不是要重构成微服务，也不是单纯堆技术，而是在现有 `bit-forum-spring` 轻量论坛基础上，先补齐社区系统的完整业务闭环，再引入 AI Agent 能力把论坛升级为智能社区平台。

第一阶段（M1-M12）已完成的业务闭环：

```text
内容发布
-> 板块组织
-> 审核发布
-> 用户互动
-> 通知反馈
-> 举报治理
-> 后台统计
-> 用户个人中心
```

第二阶段（M13-M18）新增的 AI Agent 闭环：

```text
LLM 接入
-> 多轮对话
-> 工具调用（Agent 真实操作论坛）
-> RAG 知识库检索
-> 内容审核人机协同
-> 运营分析洞察
-> 智能推荐
-> 执行轨迹与效果评估
```

> M13-M18 的完整计划书、技术勘察证据与进度记录见 `docs/graduation/ai-agent-upgrade/`。

### 用户与认证

- 用户注册。

- `AdminInterceptor` 拦截 `/api/admin/**`。
- 从 JWT 获取 `userId`。

- 校验用户角色是否为 `ADMIN`。

### 文章、评论与 Redis

- 文章发布、修改、删除、详情、分页。
- 评论发布与查询。
- 浏览量统计。
- 点赞与取消点赞。
- 热门文章排行。
- 浏览、点赞、评论前校验文章存在。
- 删除文章时清理评论与 Redis 数据。

Redis 当前用途：

- String：文章浏览量。
- Set：点赞去重。

- Set：RabbitMQ 消费幂等 `messageId`。

### RabbitMQ

- 文章发布异步消息。
- 生产者 ConfirmCallback。
- ReturnsCallback。
- `mandatory` 投递失败回调。
- 消费者手动 ACK。
- `basicNack(requeue=false)`。
- DLX / DLQ。
- Redis 幂等消费。

### M13-M18 AI Agent 升级（**已完成**）

当前状态（2026-09-19）：**六个模块全部完成并按模块本地提交**（`feat/ai-agent`，未 push）。
后端 407 项测试（398 通过 + 9 条件跳过）、前端 36 项测试全绿；
Flyway 迁移已到 V19；真实 DeepSeek 调用链路（工具调用、引用回答、AI 审核、运营洞察、推荐理由、
执行轨迹）均做过真实环境验证。

立项背景：

指导老师反馈「项目工作量不够高，是否接入大模型或人工智能技术」。经勘察确认，M1-M12 已构成完整论坛业务闭环，但技术纵深集中在传统 Web 工程能力。因此新增 M13-M18 六个 AI 模块，把项目定位升级为「基于 Spring Boot 与 React 的多智能体智能社区平台」。

核心设计：

- 四个协作 Agent：问答助手（QaAgent）、内容审核（ModerationAgent）、运营分析（AnalystAgent）、智能推荐（RecommendReasonAgent）。
- 论坛既有业务能力被重新组织为 **12 个 `@Tool` 工具**（`ArticleTools` 5 个 + `UserInteractionTools` 7 个），供 Agent 调用。
- RAG 知识库：站内已发布文章向量化存入 Redis Stack，回答带可点击引用。
- 人机协同审核：AI 给出置信度与理由，管理员标记反馈，形成可量化准确率评估。
- 可观测性：**每次 AI 调用落一条执行轨迹**（路由 → 检索 → 工具调用链 → 每步耗时 → token），
  用量按 用户 / Agent / 天 聚合并可估算成本，AI 不可用时的降级表现与原因全站统一。
- 用量预算：**已按克制版实现** `TokenBudgetGuard`（单用户每日 token/费用上限、超限统一降级、
  单次输入输出保护），明确不做套餐/充值/余额、会员等级、分布式配额中心、动态配置后台。
- 未做（明确收敛掉）：LLM-as-Judge 评估脚本、Prompt 动态管理表、管理员 AI 设置页 ——
  取舍理由见 `m18-decision-brief.md`。

关键技术决策（均经实测验证）：

| 决策 | 结论 |
| --- | --- |
| 大模型框架 | Spring AI **1.1.8**，与现有 Spring Boot 3.4.5 官方兼容，不升级 Boot |
| 大模型服务 | DeepSeek（支持 Function Calling，成本低） |
| 向量存储 | Redis 镜像从 `redis:7-alpine` 换为 `redis/redis-stack-server:7.4.0-v8` |
| 嵌入模型 | 本地 ONNX Transformers（DeepSeek 无 embedding 接口，本地模型零费用离线可跑） |
| 编排方式 | 自研轻量 Supervisor，不引入 LangChain4j 等重型框架 |

## 统一实现约束

每个模块继续使用现有项目风格：

```text
Controller
Service
Mapper
Entity
DTO
Interceptor
Config
```

M13 起新增 AI 分层风格：

```text
ai/agent          各 Agent 实现

ai/tool           @Tool 工具类与注册表
ai/rag            分块、索引、检索
ai/memory         会话记忆仓储
ai/prompt         Prompt 模板与版本
ai/observe        轨迹、预算、降级
ai/eval           效果评估
```

必须保持：

- MyBatis-Plus。
- Flyway。
- Redis。
- RabbitMQ。
- JWT + Interceptor 权限方案。
- 统一 `Result<T>` 返回结构。
- Jakarta Validation。
- 简单 React / Vite 前端结构。
- M13 起：Spring AI 1.1.8 原生 `ChatClient` + `@Tool` + `Advisor` 组合，不自研替代框架。

不要引入：

- Spring Security。
- Spring Cloud。
- Elasticsearch。
- Kafka。
- 复杂权限表。
- 复杂菜单权限。
- 分布式事务。
- Redux / Zustand。
- 复杂 UI 组件库。
- M13 起额外补充：不升级 Spring Boot 到 4.x、不引入 LangChain4j、不做模型微调、不引入 Agent 编排重型框架。

## 每个模块完成标准

每完成一个模块，必须做到：

1. 新增数据库变化必须有新的 Flyway migration。
2. Entity、DTO、Mapper、Service、Controller 分层清晰。
3. 使用统一 `Result<T>`。
4. 参数使用 Jakarta Validation。
5. 权限校验正确。
6. 不返回 `password` 等敏感字段。
7. 关键异常有明确提示。
8. 补充后端测试。
9. 后端运行 `mvn test`。
10. 涉及前端时运行 `npm run build`。
11. 更新 `docs/graduation/` 下对应模块文档。
12. 输出修改文件清单、验证结果、风险和待确认事项。

M13 起额外要求：

13. AI 调用必须可降级，论坛主流程不得因 AI 故障而阻塞或报错。
14. 工具调用必须复用现有 Service，不重复编写业务 SQL。
15. Agent 写操作必须经用户身份透传与二次确认，不豁免现有拦截器。
16. Token 消耗必须落库，可审计、可估算成本（**实现见 `ai_usage_stat`，M18**）。
17. 描述 AI 能力时必须区分「已实现」与「规划中」，不得虚构评估数据。
18. AI 调用必须有执行轨迹可查（**实现见 `ai_execution_trace` + 管理端轨迹页，M18**）；
    降级原因必须可枚举、文案全站统一（**实现见 `AiDegradeGuard`，M18**）。
