# 比特论坛项目二阶段提升计划书

## 1. 阶段目标

二阶段不是继续堆技术点，而是把当前 Spring Boot 3 论坛后端提升成一个“能演示、能讲清楚、能被测试证明”的面试项目。

核心目标有四个：

1. 新增 React 前端演示页面，让项目可以从浏览器完整演示。
2. 新增管理员权限模块，让后端具备权限隔离和内容管理能力。
3. 补充管理员相关自动化测试，证明权限、禁用、脱敏、删除等风险点可控。
4. 更新 README、演示稿和简历描述，把技术改造成果转化为可表达的项目亮点。

最终项目要能讲成：

> 第一阶段完成论坛核心后端和工程化能力，包括注册登录、JWT 鉴权、文章评论、Redis 点赞去重和热榜、RabbitMQ 异步通知、Flyway、Docker Compose 和自动化测试。第二阶段补充 React 前端演示页面和管理员后台模块，基于 role/status 字段与拦截器实现普通用户和管理员权限隔离，支持文章、评论和用户管理，并补充权限相关测试。

## 2. 总体原则

1. 每次只做一个小任务，不要一次性要求完成整个二阶段。
2. 后端权限核心逻辑你必须参与，尤其是 `role/status`、登录禁用校验、`AdminInterceptor`。
3. 重复性代码、页面初版、README 初稿可以交给 Codex 辅助。
4. 每次修改完成后固定做三件事：看修改文件、读核心代码、运行测试或启动检查。
5. 不要引入暂时讲不清的复杂技术，例如 Spring Cloud、复杂 RBAC、菜单权限、分布式事务、高并发压测。

- 能列出管理员模块最小改造文件。

### 阶段 1：文档和端口检查

目标是保证 README 与 `docker-compose.yml` 描述一致。

Codex 可完成：

### 阶段 2：新增 `role/status`

目标是为管理员权限和用户禁用打基础。

字段设计：

```sql
role varchar(20) not null default 'USER'
status tinyint not null default 1
```

建议规则：

```text
role = USER / ADMIN
status = 1 正常，0 禁用
```

建议修改文件：

```text
src/main/resources/db/migration/V2__add_user_role_status.sql
src/main/java/com/bitforum/entity/User.java
src/main/java/com/bitforum/service/UserService.java
src/main/java/com/bitforum/dto/UserResponse.java
src/test/java/com/bitforum/controller/UserControllerTest.java
```

你必须理解：

- `role` 是权限身份，`status` 是账号状态。
- 禁用用户不能只靠前端隐藏按钮，必须后端拒绝登录。
- 如果用户已登录后被禁用，旧 token 是否还能访问，取决于拦截器是否每次查库校验 `status`。

验收标准：

- 新用户默认 `USER` 且 `status=1`。
- `status=0` 用户不能登录。
- `mvn test` 通过。

### 阶段 3：新增 `AdminInterceptor`

目标是保护所有 `/api/admin/**` 接口。

权限规则：

```text
未登录：拒绝
普通用户：拒绝
管理员且 status=1：放行
```

建议修改文件：

```text
src/main/java/com/bitforum/interceptor/AdminInterceptor.java
src/main/java/com/bitforum/config/WebMvcConfig.java
src/main/java/com/bitforum/service/UserService.java
src/test/java/com/bitforum/controller/AdminAuthTest.java
```

你必须理解并能画出流程：

```text
请求 /api/admin/**
-> 读取 Authorization
-> 解析 JWT 得到 userId
-> 查 user_info
-> 判断用户存在
-> 判断 status=1
-> 判断 role=ADMIN
-> 放行或拒绝
```

验收标准：

- 普通用户访问管理员接口被拒绝。
- 管理员用户可以访问。
- `mvn test` 通过。

### 阶段 4：管理员文章管理

目标是管理员可以查看和删除任意文章。

接口建议：

```text
GET    /api/admin/article/page?pageNum=1&pageSize=10
DELETE /api/admin/article/delete?articleId=1
```

重点不是删除接口本身，而是复用现有文章删除的数据清理逻辑：

```text
删除文章
-> 删除评论
-> 删除文章记录
-> 清理 Redis 浏览量
-> 清理 Redis 点赞集合
-> 清理 Redis 热榜成员
```

建议修改文件：

```text
src/main/java/com/bitforum/controller/AdminArticleController.java
src/main/java/com/bitforum/service/ArticleService.java
src/test/java/com/bitforum/controller/AdminArticleControllerTest.java
```

验收标准：

- 管理员可分页查看文章。
- 管理员可删除任意文章。
- 普通用户不能访问管理员删除接口。
- 删除后评论和 Redis 数据被清理。

### 阶段 6：管理员用户管理

目标是管理员可以查看用户、禁用用户、启用用户。

接口建议：

```text
GET /api/admin/user/page?pageNum=1&pageSize=10
PUT /api/admin/user/disable?userId=1
PUT /api/admin/user/enable?userId=1
```

关键规则：

```text
用户列表不能返回 password
管理员不能禁用自己
禁用用户后不能再次登录
普通用户不能修改 role/status
```

建议修改文件：

```text
src/main/java/com/bitforum/controller/AdminUserController.java
src/main/java/com/bitforum/service/UserService.java
src/main/java/com/bitforum/dto/AdminUserResponse.java
src/test/java/com/bitforum/controller/AdminUserControllerTest.java
```

验收标准：

- 管理员可分页查看用户。
- 用户列表不返回密码。
- 管理员可禁用/启用普通用户。
- 管理员不能禁用自己。
- 被禁用用户不能登录。

## 6. 下一步建议任务

建议下一步先做阶段 2，不要先做 React。

原因是 React 管理员后台依赖后端管理员接口。如果后端权限链路没完成，前端只能做静态页面，演示价值不高。

下一条可以发给 Codex 的任务：

```text
请只为用户模块增加 role 和 status 字段，不要新增管理员接口。

要求：
1. 使用 Flyway 新增迁移脚本，不修改已有 V1 脚本。
2. user_info 新增 role varchar(20) not null default 'USER'。
3. user_info 新增 status tinyint not null default 1。
4. 更新 User 实体。
5. 注册用户默认 role=USER、status=1。
6. 登录时校验 status=1，否则拒绝登录。
7. 补充或更新测试，至少覆盖禁用用户不能登录。
8. 运行 mvn test。
9. 完成后列出修改文件和测试结果。
```

## 8. 二阶段真正的项目价值

二阶段完成后，不要只说“我加了管理员页面”。

更好的说法是：

> 我补充了基于角色的权限隔离，管理员接口统一走 `/api/admin/**`，后端通过拦截器校验 JWT、用户状态和角色。管理员支持文章、评论和用户管理，禁用用户会影响登录认证流程，并通过自动化测试覆盖普通用户越权、管理员自禁用、用户信息脱敏等风险点。同时新增 React 前端演示页面，让项目可以完整展示普通用户和管理员两条使用路径。
