# React 前端学习路线

## 1. 文档定位

这个文档只记录二阶段 React 前端演示页面的学习路线和实施节奏。

原来的 `docs/phase2-plan/项目二阶段提升计划.md` 继续作为二阶段总规划使用；本文件用于前端专项学习，避免把后端管理员模块、测试计划和前端页面实现混在一起。

当前前端分支：

```text
phase-2-react-frontend
```

当前目标：

```text
用 React + Vite + Axios 做一个简洁的论坛前端演示页面，能完整演示注册、登录、文章、评论、点赞、热门文章和管理员后台。
```

## 2. 总体原则

1. 每次只做一个小任务，不一次性写完整前端项目。
2. 先理解目录结构和数据流，再继续写页面。
3. 页面先保证能联调和能演示，再考虑样式优化。
4. 前端只做用户体验和请求封装，真正权限仍然由后端拦截器控制。
5. 每完成一步，都记录：
   - 改了哪些文件
   - 新增了什么代码
   - 前端流程发生了什么变化
   - 应重点理解哪些前端知识点

## 4. 七步学习路线

### 第一步：搭建 React + Vite 项目结构

目标：

```text
创建 frontend 目录，让 React 项目能启动，先显示一个最小页面。
```

计划安装依赖：

```powershell
npm create vite@latest frontend -- --template react
cd frontend
npm install
npm run dev
```

命令作用：

```text
npm create vite@latest frontend -- --template react
创建一个名为 frontend 的 React + Vite 项目。

npm install
根据 package.json 安装项目依赖。

npm run dev
启动 Vite 开发服务器。
```

本步重点理解：

```text
Vite 是开发服务器和构建工具。
React 用组件描述页面。
main.jsx 是前端入口。
App.jsx 是当前应用的根组件。
```

验收标准：

```text
浏览器能打开 Vite 页面。
frontend 目录结构清晰。
不接后端接口。
```

### 第二步：讲清楚前端目录结构

目标：

```text
把页面、接口请求、应用入口分清楚。
```

本步会整理：

```text
src/api      放 axios 请求封装
src/pages    放页面组件
App.jsx      控制当前展示哪个页面
main.jsx     挂载 React 应用
style.css    放简单样式
```

本步重点理解：

```text
组件是什么。
页面组件和普通组件有什么区别。
为什么 API 请求要单独放到 api 目录。
```

验收标准：

```text
能说清楚点击一个按钮后，代码大概从页面组件走到哪里。
```

### 第三步：封装 Axios 请求

目标：

```text
封装统一请求实例，并自动给需要登录的接口带上 Authorization: Bearer <token>。
```

预计新增文件：

```text
src/api/request.js
src/api/userApi.js
src/api/articleApi.js
src/api/commentApi.js
src/api/adminApi.js
```

本步重点理解：

```text
baseURL：后端 API 地址。
请求拦截器：发请求前统一加 token。
响应拦截器：统一处理 code/message/data。
localStorage：先用它保存演示用 token。
```

验收标准：

```text
登录接口能拿到 token。
后续写接口能自动带 token。
```

### 第四步：做登录/注册页面

目标：

```text
完成普通用户注册、登录、保存 token。
```

对接接口：

```text
POST /api/user/register
POST /api/user/login
```

请求体：

```json
{
  "username": "testuser",
  "password": "123456"
}
```

登录成功后保存：

```text
token
userId
username
```

本步重点理解：

```text
useState 管理输入框。
表单提交如何阻止默认刷新。
登录成功后为什么要保存 token。
前端保存 token 只是为了后续请求方便，不代表权限可信。
```

验收标准：

```text
能注册新用户。
能登录并保存 token。
登录失败能看到后端返回的 message。
```

### 第五步：做文章列表/详情/发布

目标：

```text
普通用户可以看文章、看详情、发布文章。
```

对接接口：

```text
GET  /api/article/page?pageNum=1&pageSize=10
GET  /api/article/detail?articleId=1
GET  /api/article/view?articleId=1
POST /api/article/publish
```

发布文章请求体：

```json
{
  "title": "第一篇文章",
  "content": "这是文章内容"
}
```

本步重点理解：

```text
useEffect 页面加载时请求数据。
分页数据在 data.records / data.total / data.pages。
发布文章接口为什么必须带 token。
view 接口会让 Redis 浏览量加 1。
```

验收标准：

```text
文章列表能展示。
点击文章能进入详情。
登录后能发布文章。
发布后列表能看到新文章。
```

### 第六步：做点赞/评论/热门文章

目标：

```text
补齐论坛核心互动演示。
```

对接接口：

```text
POST /api/article/like?articleId=1
POST /api/article/unlike?articleId=1
GET  /api/comment/listAll?articleId=1
POST /api/comment/publish
GET  /api/article/hot
```

评论请求体：

```json
{
  "articleId": 1,
  "content": "这是一条评论"
}
```

本步重点理解：

```text
点赞为什么要登录。
后端如何用 Redis Set 做点赞去重。
热门文章来自 Redis ZSet。
评论发布后为什么要重新拉取评论列表。
```

验收标准：

```text
能点赞或取消点赞。
能查看和发布评论。
热门文章页面能展示 hotScore。
```

### 第七步：做管理员页面

目标：

```text
管理员可以管理文章、评论和用户。
```

对接接口：

```text
GET    /api/admin/health
GET    /api/admin/article/page?pageNum=1&pageSize=10
DELETE /api/admin/article/delete?articleId=1
GET    /api/admin/comment/page?pageNum=1&pageSize=10
DELETE /api/admin/comment/delete?commentId=1
GET    /api/admin/user/page?pageNum=1&pageSize=10
PUT    /api/admin/user/disable?userId=2
PUT    /api/admin/user/enable?userId=2
```

本步重点理解：

```text
前端隐藏按钮不是权限控制。
/api/admin/** 的权限由 AdminInterceptor 校验。
AdminInterceptor 会校验 JWT、用户状态 status、用户角色 role。
禁用用户后，被禁用用户不能再次登录。
管理员不能禁用自己。
```

验收标准：

```text
管理员 token 可以进入后台。
普通用户 token 访问后台会被后端拒绝。
能删除文章、删除评论、启用/禁用用户。
```

## 5. 接口响应约定

后端统一返回：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

前端处理原则：

```text
code === 200：认为业务成功，使用 data。
code !== 200：认为业务失败，展示 message。
HTTP 401：未登录或 token 过期。
HTTP 403：无权限或账号不可用。
```

分页接口重点字段：

```text
data.records  当前页数据
data.total    总条数
data.pages    总页数
data.current  当前页
data.size     每页条数
```

## 6. 页面顺序建议

先做普通用户路径：

```text
注册 -> 登录 -> 文章列表 -> 文章详情 -> 发布文章 -> 评论 -> 点赞 -> 热门文章
```

再做管理员路径：

```text
管理员登录 -> 管理员权限验证 -> 文章管理 -> 评论管理 -> 用户管理
```

这样学习时能先理解最常见的前端请求流程，再理解权限和后台管理。
