# 面试前最终改进清单

## 使用方式

这份清单用于面试或投递前最后检查。不要临场大改代码，只确认项目能跑、核心功能能演示、关键话术能讲清楚。

建议顺序：

```text
环境检查 -> 自动化测试 -> Docker 启动 -> 接口演示 -> RabbitMQ/Redis 展示 -> 文档复习
```

## 1. 环境检查

### 必须确认

- Docker Desktop 已启动。
- 本机没有占用这些端口：`8080`、`3306`、`6379`、`5672`、`15672`。
- 如果用本地方式运行项目，确认本机 MySQL、Redis、RabbitMQ 已启动。
- 如果用 Docker Compose 方式运行项目，优先让 Compose 启动 MySQL、Redis、RabbitMQ 和 app。

### 常用命令

```powershell
cd D:\ClaudeCode\BitFrom\spring_code\bit-forum-spring
docker compose config
docker compose ps
```

### 看到什么算正常

- `docker compose config` 能正常输出配置。
- `docker compose ps` 中 MySQL、Redis、RabbitMQ、app 都是 running/up 状态。

## 2. 自动化测试验收

### 命令

```powershell
mvn test
```

### 看到什么算正常

```text
BUILD SUCCESS
Failures: 0
Errors: 0
```

### 面试讲法

我补的测试主要覆盖核心业务规则，不是单纯追求数量。比如注册登录参数校验、发布文章发送 MQ、Redis 点赞去重、热门排行、非作者删除失败、评论不存在文章失败、RabbitMQ 重复消息 ACK。

## 3. Docker 启动验收

### 命令

```powershell
docker compose up --build
```

### 重点观察

- 后端日志出现 Spring Boot 启动完成。
- RabbitMQ 管理台可打开：`http://localhost:15672`
- RabbitMQ 管理台账号密码：参考本地 `.env`，模板见 `.env.example`
- 后端接口端口：`http://localhost:8080`

### 面试讲法

我使用 Docker 多阶段构建后端镜像，builder 阶段用 Maven 从源码打包，runtime 阶段用 JRE 运行 jar。然后用 Docker Compose 编排 MySQL、Redis、RabbitMQ 和后端服务，一条命令可以启动完整环境。

## 4. 核心接口演示

### 4.1 注册

```http
POST /api/user/register
Content-Type: application/json
```

```json
{
  "username": "testuser",
  "password": "123456"
}
```

验收点：

- 返回用户基础信息。
- 不返回 password 或 password hash。

面试讲法：

注册接口返回 `UserResponse`，不直接返回数据库实体 `User`，避免把密码哈希等敏感字段暴露给前端。

### 4.2 登录

```http
POST /api/user/login
Content-Type: application/json
```

```json
{
  "username": "testuser",
  "password": "123456"
}
```

验收点：

- 返回 `data.token`。
- 后续写接口都带 `Authorization: Bearer <token>`。

面试讲法：

登录成功后返回 JWT，写接口通过拦截器解析 token，拿到 userId 后放到 request attribute，避免前端手动传 userId。

### 4.3 发布文章

```http
POST /api/article/publish
Content-Type: application/json
Authorization: Bearer <token>
```

```json
{
  "title": "第一篇文章",
  "content": "这是文章内容"
}
```

验收点：

- 接口返回发布成功。
- RabbitMQ 消费者日志能看到文章发布消息。

面试讲法：

发布文章主流程保存数据，通知逻辑通过 RabbitMQ 异步处理，降低主流程耦合。

### 4.4 分页查询

```http
GET /api/article/page?pageNum=1&pageSize=10
```

验收点：

- 返回分页结果。
- 能看到 `records`、`total`、`pages`、`current`、`size` 等分页信息。

### 4.5 浏览文章

```http
GET /api/article/view?articleId=1
```

验收点：

- 文章存在时浏览成功。
- Redis 浏览量加 1。
- 热度分数加 1。

### 4.6 点赞文章

```http
POST /api/article/like?articleId=1
Authorization: Bearer <token>
```

验收点：

- 同一用户重复点赞不会重复增加点赞数。
- 热度分数加 3。

面试讲法：

点赞用 Redis Set，因为 Set 天然去重；热门排行用 Redis ZSet，因为 ZSet 适合按分数排序取 Top N。

### 4.7 热门排行

```http
GET /api/article/hot
```

验收点：

- 返回热门文章列表。
- 排序来自 Redis ZSet。

### 4.8 发布评论

```http
POST /api/comment/publish
Content-Type: application/json
Authorization: Bearer <token>
```

```json
{
  "articleId": 1,
  "content": "这是一条评论"
}
```

验收点：

- 文章存在时评论成功。
- 文章不存在时评论失败，不插入脏评论。

## 5. RabbitMQ 展示

### 管理台

```text
http://localhost:15672
账号密码见本地 .env
```

### 重点看什么

- `article.exchange`
- `article.publish.queue`
- `article.publish.dlq`
- 普通队列是否带有 DLX 参数

### 面试讲法

我的 RabbitMQ 链路不是只发一个字符串消息，而是使用结构化消息 `ArticlePublishMessage`，里面有 `messageId`、`articleId`、`userId`、`title`、`publishTime`。

生产者用 Confirm/Returns 观察消息是否到达 Broker、是否成功路由到队列；消费者使用手动 ACK，失败时 `basicNack(requeue=false)`，失败消息进入 DLQ；重复消费通过 Redis Set 记录 `messageId` 做幂等。

## 6. Redis 展示

### 重点数据结构

| 数据结构 | 用途 | 示例 |
| -------- | ---- | ---- |
| String | 浏览量 | `article:{id}:views` |
| Set | 点赞去重 | `article:{id}:likes` |
| ZSet | 热门排行 | `article:hot` |

### 面试讲法

Redis 不是随便用缓存，而是按业务选择数据结构。浏览量是计数器，用 String；点赞要去重，用 Set；热门排行要按分数排序，用 ZSet。

## 7. 常见失败排查

| 现象 | 可能原因 | 处理 |
| ---- | -------- | ---- |
| Docker API 连接失败 | Docker Desktop 没启动 | 启动 Docker Desktop |
| MySQL 3306 端口冲突 | 本机 MySQL 占用端口 | 停掉本机 MySQL，或把 Compose 改成 `3307:3306` 并同步 README |
| Public Key Retrieval is not allowed | MySQL 8 认证问题 | JDBC URL 加 `allowPublicKeyRetrieval=true` |
| RabbitMQ Connection refused | RabbitMQ 启动比 app 慢 | 观察后续是否重连成功 |
| 队列参数不一致 | RabbitMQ 已有旧队列 | 删除旧队列后让项目重新声明 |
| Maven 依赖下载失败 | 网络或仓库连接问题 | 重试或检查 Maven 镜像配置 |
